# 07 – Funktions- und Testmatrix

Stand: 2026-11-18 · Codestand `0c8013e`

## 1. Wie diese Matrix entstanden ist

- **Funktionskatalog:** technische Inventur ausschließlich aus dem Quellcode (85 Funktionen mit Beleg `Datei:Zeile`), danach mit dem README abgeglichen (Abschnitte 5 und 6 unten).
- **Status Umsetzung:** implementiert / teilweise implementiert / nur dokumentiert / nicht vorhanden. Befunde, die in dieser Runde behoben wurden, sind gekennzeichnet.
- **Status Test:** „implementiert und getestet“ nur, wenn in dieser Runde ein automatisierter Test die Funktion tatsächlich ausgeführt hat. Alles andere heißt „nicht getestet“ – auch wenn die Funktion in einer früheren Runde schon einmal geprüft wurde. Es werden keine Tests behauptet, die nicht gelaufen sind.
- **Testbelege:** `VAL` Drehbuchprüfung · `VAR` Variantenprüfung · `LAUF` Lauftest mit echtem Server und SMTP-Testempfänger · `BUE` Browsertest (Chromium) · `SEC` Sicherheitstest · `GES` Geschichten-Generator · `MED` Medienliste. Ergebnisse: `testberichte/testbericht.md` und Rohdaten im selben Ordner.

**Ergebnis der automatisierten Prüfungen dieser Runde:** 67 von 67 bestanden; Drehbuch- und Variantenprüfung beider Szenarien ohne Befund.

### 5. Im README behauptet, im Code nicht gefunden

Nicht gefunden:
1. **Ausschließlich lokaler Betrieb** (README:85 "Die App läuft ausschließlich lokal"; ebenso `public/index.html:11`). Der Server bindet ohne Host-Angabe an alle Schnittstellen (`server/index.js:1415`); die Daten unter `data/` (README:510-512) sind damit über die API für jedes Gerät im Netz erreichbar.
2. **PDF als Medientyp** (README:442 "Weitere Dateien (Bilder, Video, PDF) ablegen"). `renderMedia` kennt nur Video und Bild (`public/stage.js:355-371`).
3. **Bewertungsmatrix / Bewertungskriterien** (README:15, README:510 "Bewertungen"; `package.json:5` "Bewertungsmatrix"). Es gibt nur den Endpunkt `POST /api/bewertung` ohne Oberfläche; `bewertungskriterien` wird nur durchgereicht (`server/index.js:436,1289`).

Abweichungen zwischen README und Code bzw. Daten:
4. **Vorboten-Dauer** (README:289-290 "Vorboten kosten nur 2 Minuten Lesezeit"). Code nutzt `standardablauf.vorbotenMinuten` (`server/runEngine.js:130-132`), in beiden Drehbüchern 3 Minuten; 2 ist nur der Standardwert.
5. **87 Minuten im Modus "Erprobte Zeiten"** (README:306-307). Rechnerisch ergibt `totalPlannedMinutes` bei Vollbesetzung für beide Drehbücher 92 Minuten (`server/runEngine.js:573-575`, per Skript ermittelt).
6. **"Nur angehakte Rollen erscheinen … bei 'Manuell auslösen'"** (README:126-127). Die Moderation filtert nach besetzter Empfängerrolle, nicht nach angehakten Rollen (`public/moderator.js:317,324`).
7. **Mengendeckel vertraulicher Karten** (README:297-299, ohne Einschränkung formuliert). Gilt nur im Modus Zieldauer (`server/runEngine.js:428-436`); in den anderen Modi werden alle erreichbaren terminierten Karten verschickt.
8. **Sparsamer Toneinsatz, "genau ein Kontrast-Moment"** (README:475-481). NordTech hat Töne bei 11 Lagekarten und 3 Bonuskarten (per Skript aus `data/scenario.nordtech.json` ermittelt); für Waterkant stimmt die Aussage (1 Lagekarte).
9. **Gleiche Funktion unter Windows, macOS und Linux** (README:46-48): Im Code sind keine plattformspezifischen Pfade erkennbar (`path.join` durchgängig); ob es so getestet wurde, ist unklar.
