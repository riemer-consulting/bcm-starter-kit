# 6. Kritikalität verstehen und dokumentieren

## Wofür ist diese Funktion da?

Die Kritikalität legt fest, wie wichtig ein Prozess für die
Fortführung Ihres Unternehmens ist. Sie steuert, wie stark der Prozess
in Auswertungen (Management Summary, GF-Ansicht, Governance Dashboard)
gewichtet wird, und ob bestimmte Freigabe-Regeln greifen (z. B. verlangt
das Starter Kit für einen kritischen Prozess einen dokumentierten
Notbetrieb, bevor eine Freigabe möglich ist).

## Wo finde ich sie?

Im Steckbrief-Reiter jeder Prozessakte, unter "Kritikalität & Zeitwerte":
**Hoch**, **Mittel** oder **Niedrig**.

## Wie treffe ich die Einstufung?

Die Kritikalität ist immer eine **manuelle, bewusste Entscheidung** —
das Starter Kit setzt sie nie selbst. Es unterstützt Sie aber mit einer
**Empfehlung**, die aus Ihrer Business-Impact-Analyse (siehe
[Kapitel 7](07-bia.md)) berechnet wird: Ein hoher gewichteter
Durchschnittswert über alle Auswirkungskategorien deutet auf einen
kritischen Prozess hin, ein niedriger auf einen weniger kritischen.

## Was das Starter Kit automatisch macht

Sobald Sie die BIA für einen Prozess ausgefüllt haben, zeigt das
Starter Kit im Steckbrief an, wenn Ihre manuelle Einstufung von der
BIA-Empfehlung abweicht — z. B. "Manuelle Kritikalität: Mittel · BIA-
basierte Empfehlung: Hoch". Das ist kein Fehler und wird auch nicht
automatisch korrigiert.

## Was ich selbst entscheiden muss

Weicht Ihre Einstufung von der Empfehlung ab, können — und bei einer
späteren Freigabe müssen — Sie das kurz begründen (Feld "Begründung der
Abweichung" direkt unter dem Hinweis). Das ist ausdrücklich erlaubt: Die
BIA ist eine Rechenhilfe, keine Vorschrift. Es gibt legitime Gründe für
eine Abweichung — zum Beispiel regulatorische Vorgaben, die eine
bestimmte Einstufung verlangen, unabhängig vom BIA-Ergebnis.

## Typische Fehler

- Die Kritikalität nur einmal beim Anlegen setzen und nie wieder
  prüfen, obwohl sich der Prozess seither verändert hat. Eine
  regelmäßige Reviewplanung für den Prozessreview beugt das vor (siehe
  [Kapitel 18](18-reviewzyklen.md)).
- Eine Abweichung von der BIA-Empfehlung stehen lassen, ohne sie zu
  begründen — das fällt spätestens bei der Freigabe auf (siehe
  [Kapitel 24](24-freigabe.md)).

## Wo die Kritikalität überall wirkt

- Im Governance Dashboard werden Aufgaben zu kritischen Prozessen
  bevorzugt priorisiert (siehe [Kapitel 21](21-governance-dashboard.md)).
- Ein kritischer Prozess ohne jegliche Reviewplanung wird explizit
  hervorgehoben (siehe [Kapitel 17](17-review-center.md)).
- Ein kritischer Prozess ohne dokumentierten Notbetrieb blockiert eine
  Freigabe (siehe [Kapitel 24](24-freigabe.md)).
- Auf der Prozessübersicht sowie in der GF-Ansicht sehen Sie zusätzlich
  eine automatisch berechnete Ampel je Prozess (rot/gelb/grün) — sie
  fasst mehrere Signale zusammen (z. B. fehlender Notbetrieb, kritische
  Ressource ohne Alternative, unbearbeiteter roter Resilienzpunkt). Ein
  Klick auf die Ampel bzw. die GF-Ansicht zeigt die konkreten Gründe.
